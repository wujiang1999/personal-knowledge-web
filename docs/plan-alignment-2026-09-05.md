- **审阅对象**：personal-knowledge-web（sjtuai.art，Next.js 16 + PG16 + pgvector，9f35bbe）
- **对照标准**：用户 2026-09-05 提供的《个人知识库项目规划》——采集→整理→检索→纠错→备份 闭环，三层能力（基础知识管理 / 智能化 / 可靠性），P0/P1/P2 路线
- **方法**：代码只读盘点（17 个 API 路由、14 个迁移、lib/scripts/components 全量）+ 线上实勘（服务器检出 9f35bbe 与本地/GitHub 三端一致；15 条 stable 概念；pgvector 0.6.0 + 12 条向量在线）

## 一、总体结论

**规划中的 P0 基础闭环大部分已经落地，且多项提前实现了 P2 内容。** 当时的架构评审（2026-08-28）解决的是主机与运维层；此后应用层按"Obsidian 范式三批迭代"（2026-09-04）补齐了链接网络、搜索算子、模板、图谱等能力。本次对照规划逐项盘点后，真正的结构性缺口收敛为四个，均已在本轮迭代中修复（见第三节）。

### 规划核心缺口（本轮已修复）

1. **版本回滚与 diff 缺失**（规划 §一.7"历史版本、版本差异、回滚"属 P0）——版本只能看不能用，"编辑错误要能恢复"不成立。
2. **删除是一步硬删除**（规划 §一.7"归档、回收站或软删除"）——DELETE 直接 CASCADE 连版本带附件全部销毁，误删不可挽回；违背验收项"删除或归档后不会继续被默认检索"（无从谈起）与"编辑错误要能恢复"。
3. **OKF 只有导出没有导入**（规划 P0 行明确要求"基础 OKF 导入导出"；§一.9"导入恢复"）——迁移/恢复闭环缺另一半。
4. **重复/冲突治理只有半套**（规划 §三，"最关键的模块"）——写入侧有 409 精确查重、ingest 有阈值跳过，但同名不同内容的冲突没有显式的"人工裁决"出口，导入场景下会静默制造同名条目。

### 规划中暂不落地的项（有意推迟，非遗漏）

| 项 | 规划定位 | 推迟理由 |
|---|---|---|
| 异步任务表（阶段/重试/幂等） | §四 P1 | 当前唯一异步是自动摘要，失败仅降级描述为空、原文无损；等 LLM 批处理变重（如全库重摘要、批量 ingest 队列）再建任务表不迟 |
| 带引用 AI 问答（RAG 入口） | §二 P2 | 检索层已是混合检索，缺的是答案合成层；先把"找得准、看得懂来源"用满，问答入口价值才成立 |
| 冲突审核队列 UI（多选项裁决台） | §三 | 本轮以"导入冲突报告 + 明确不覆盖"兜住最常见的冲突入口；完整的待审核队列（保留旧/采用新/合并/分别保留四选项）需要独立的审核状态机，列为下一轮 |
| OKF 导出含历史版本/附件 | §一.9 | 当前导出=有效知识快照；全量导出（含版本树/附件/来源）建议与"任务表"一起做，避免一次性巨型 ZIP |
| 多租户/图数据库/多 Agent/微调 | 规划明确暂缓 | 个人规模不适用 |

## 三、本轮迭代交付（2026-09-05）

对应上面四个缺口，一次性闭环：

1. **回收站（软删除）**：迁移 0015 `concepts.deleted_at` + 双部分索引；DELETE 语义改为入回收站，`?purge=1` 才彻底删除且只对已回收条目生效（两段式销毁，服务端 409 拦一步到位）；新增 `/trash` 页面、`GET/DELETE /api/trash`、恢复端点；列表/搜索（BM25/算子/ trgm）/语义召回/图谱/导出/链接网络/curate/查重/摘要/embed-backfill **全部查询面排除已删除条目**；详情页对回收站条目显示横幅并允许恢复。
2. **版本回滚 + 对比**：`POST /api/concepts/[id]/versions/[v]/restore`——按"历史不可变"原则把旧版本生成为**新版本**（回滚本身可再回滚）；详情页版本历史支持"对比当前"（自研 LCS 行 diff，超限整块替换兜底）与一键回滚。
3. **OKF 导入**：`POST /api/import/okf`（≤20MB ZIP）+ 设置页上传 UI；逐文件解析，按规划 §三分类：内容完全相同→**复用已有条目**（duplicate），同名不同内容→**冲突不覆盖**（conflicts 报告留人工裁决），其余新建；解析失败逐文件进 errors，不阻塞也不谎报成功；往返导出→导入自检通过。
4. **MCP 同步（契约变更，同会话完成）**：v0.5.0——`kb_delete_concept` 语义更新 + `purge` 参数；新增 `kb_restore_concept` / `kb_restore_version` / `kb_list_trash` / `kb_empty_trash`（confirm 门禁）；README 工具参考 12→16。

**验收口径（对应规划最终验收清单）**：重复导入不产生重复正式知识（✅ 导入分类 + 写路径 409 双层）；冲突未经确认不覆盖旧知识（✅ 导入 conflicts + purge 两段式）；删除或归档后不会继续被默认检索（✅ 全查询面过滤，语义向量同样过滤）；误删可恢复（✅ 回收站 + 版本回滚）；全新环境恢复（原有备份/演练闭环不变）。
